# Скилл статей - навык написания SEO-статей

Запускает полный процесс написания и публикации SEO-статьи по методологии **16 этапов** (`methodology/00-methodology-16-stages.md`).

## Приоритет документов (обязательно)

Если правила расходятся, старше тот, кто выше в списке:

1. `methodology/editorial-standard.md` - смысл, язык, структура, факты, SEO-эвристики. Старше механических квот и «AI-score».
2. `methodology/topic-selection.md` - выбор темы по свежим данным каждый день; повторная проверка перед каждым слотом; резервы и правило двух попыток.
3. `methodology/final-review.md` - обязательный финальный каскад: независимый редактор (другая модель) + свежий проверяющий ДО публикации, контроль версии по SHA-256.
4. `methodology/owner-report.md` - одно короткое уведомление владельцу по контракту.
5. `methodology/00-methodology-16-stages.md` - подробности всех этапов.

Нельзя обещать обход ИИ-детекторов, гарантированную индексацию или трафик - ни в статье, ни в отчёте владельцу.

## Перед первым запуском

Должен быть заполнен `config.yaml` (домен, аудитория, голос, оффер, стоп-слова, способ публикации, юрисдикция `legal.region`, канал отчёта `notify.channel`, финальный каскад `qa.final_review`). Если его нет - сначала прогнать `AUTOPILOT.md` (он соберёт конфиг, изучив проект).

## Когда триггериться

- «Напиши статью про <тему>» - тема задана, начать с Этапа 3 (заголовок).
- «Запусти Скилл статей» / «нужна новая статья» - темы нет, начать с Этапа 1 (автономный выбор темы).
- «Построй статью», «новая SEO-статья», «статья в блог про X».

**НЕ триггериться:** правка уже опубликованной статьи (это ручная правка + переиндексация по отдельному регламенту, не этот workflow), общий вопрос «как устроен Скилл статей» (ответ из методологии без запуска).

## Главное правило - autonomous mode

Любой запуск = автономный режим. Агент не ждёт «ОК» между этапами, доводит статью до публикации, пишет ретроспективу и завершает. Останавливается только в 5 случаях (gate-условия):

1. **Тема слабая** (балл ниже порога по 9 осям / неподтверждённые доказательства спроса) → не пишем, берём в backlog, завершаем.
2. **Критичное QA-нарушение** (выдуманная цитата/цифра, нарушение `editorial.banned_words`, обещание гарантированного результата, self-disclosure утечка) не закрылось за 3 итерации автоисправления → статья остаётся черновиком, пишем причину.
3. **Финальный каскад** (`final-review.md`) дал третий reject или модель-редактор недоступна → черновик, пишем блокер.
4. **Визуальная проверка рендера** провалилась дважды подряд → черновик, пишем что сломано.
5. **Публикация через `cms.adapter`** вернула ошибку → пишем traceback и состояние, чините руками.

Во всех остальных случаях - продолжаем, не спрашиваем. Если запуск был слотом расписания и тема провалилась - правило двух попыток из `topic-selection.md`: берём следующую тему из пула, не заканчиваем на «не получилось».

## Что делать при активации

1. Прочитать `config.yaml`, документы приоритета (выше) и `checklists/` - полностью.
2. Если есть `voice.source` - прочитать образцы голоса для тон-матчинга.
3. Создать рабочий чек-лист из `checklists/_CHECKLIST-TEMPLATE.md` → `work/<slug>.checklist.md` (Этап 0a).
4. Идти по 16 этапам сверху вниз, не пропуская, закрывая пункты чек-листа только при наличии артефакта в `work/<slug>/`.
5. Финальный gate перед завершением: `grep -c "\[ \]" work/<slug>.checklist.md` = 0.
6. Финальное сообщение владельцу - одно короткое, по `methodology/owner-report.md`.

Полный процесс - в `methodology/00-methodology-16-stages.md`.
